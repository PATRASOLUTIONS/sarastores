Credentials and scope

Existing local credentials were not used or changed. Runtime fixtures use random synthetic keys. Real Pine Labs UAT completion remains blocked by the missing PINELABS_CALLBACK_SECRET signing key. Real Paytm staging completion requires merchant-issued PAYTM_MERCHANT_ID and the 16-byte PAYTM_MERCHANT_KEY; they are not public shared test credentials. No third-party merchant secrets were obtained.

Official Paytm testing guide describes staging test instruments and success/failure simulations. Official Initiate Transaction API, merchant API-key documentation. Public test instruments do not replace onboarding/dashboard merchant keys; these journeys did not use card details.

All screenshots contain synthetic data only. External analytics/payment/CAPTCHA network requests were blocked or intercepted. Browser automation uses native text input, keyboard consent, native pointer product selection, and DOM activation of actual visible form buttons. Development-navigation retries were needed; completed steps were retained and failed steps re-run against the same synthetic account. No business handlers or authentication/payment checks were bypassed. This is development-mode functional evidence, not performance, real-bank settlement, or a full gateway failure/idempotency audit.

Reproduce safely

Use a fresh explicitly isolated database name under ecom_sara_audit_, never the live store database. Start node scripts\audit-journey-server.mjs <isolated-db> gateways, launch a dedicated Chrome profile with debugging port 9226, then run node scripts\audit-gateway-browser.mjs <isolated-db>. Ports 3025, 1587 and 1588 must be free. The fixture server redirects all payment provider calls locally and refuses non-isolated DB access in the application. After stopping the owned processes, run node scripts\audit-journey-server.mjs <isolated-db> cleanup to remove the marker-guarded synthetic records.
